# 交互式 Spec 的验收 / QA 清单

## 信息正确性

- [ ] 已阅读全文，包含 Problem、Solution、Stories、Implementation、Testing、Out of Scope。
- [ ] 已区分“原文事实 / 推导出的建议 / 原型模拟 / 实际已实现”。
- [ ] 每个图的节点和边都有意义；依赖边确有前置条件依据。
- [ ] 每条重要异常、拒绝、回滚、警告策略与 Spec 一致。
- [ ] 未添加明确 Out of Scope 的产品功能。
- [ ] 没有来源的文件路径、API 端点和进度不以事实呈现。

## 可视化与产品交互

- [ ] 首屏能看出主交付、开发入口和并行关系。
- [ ] 点击阶段能看出前置、后续、影响文件/模块、验收点。
- [ ] 系统图能看出对象之间真实的数据传递或状态变化。
- [ ] UI 原型覆盖至少一条完整业务路径，而非静态截屏。
- [ ] 至少一条失败/边界路径可主动触发，图和 UI 同步反馈。
- [ ] 提供一键重置或可恢复的可重复演示路径。
- [ ] 在图、UI、矩阵之间的实体 ID/需求 ID 一致。
- [ ] 所有“模拟”均清晰标明，不伪称连真实后端。

## 技术与视觉 QA

- [ ] HTML 双击打开即可使用，无构建依赖和 CDN 资源。
- [ ] 主要控件用键盘可以操作，焦点状态清晰。
- [ ] 桌面约 1440×900、手机约 390×844 下可读、无严重遮挡与横向溢出。
- [ ] 展开/切换/选择/提交/重置后没有 JS 异常。
- [ ] 测试至少一次正常路径、一次约束错误路径、一次 UI 恢复路径。
- [ ] 文字不靠无意义口号填充；技术细节按需展开。
- [ ] 生成物不包含生产密钥、真实个人数据或未经允许的内部信息。

## 推荐交付结构

- `visual-spec.html` — 离线单文件。
- `source` — 明确的原 Issue/文档链接及其版本或读取时间。
- `coverage` — 说明覆盖了哪些主要业务链路、哪些仅保留文字追溯。
- `limitations` — 说明图是原型、实施顺序属于建议、没有真实后端连接。
